# 06 — 테스트, 완료 기준 및 Vercel 배포

## 자동 테스트
### 단위 테스트 (Vitest)
- 모델 기본가 300000원 + 부품 45000원 = 345000원.
- 기본 중량 2500g + 부품 180g = 2680g.
- 예산보다 기본 모델이 비싸면 422 및 한국어 안내.
- verified 부품만 후보에 포함.
- 같은 슬롯 부품 중복 불가.
- 동일 입력/데이터는 동일 추천 결과.
- AI 설명 실패 시 규칙 기반 설명으로 대체.
- 이미지 검색 결과의 잘못된 URL 스킴 제거.
- 이미지 검색 결과 0개일 때 기본 모델 이미지 유지.

### 통합 테스트
- `GET /api/models`: 정상, DB 오류.
- `GET /api/accessories`: 정상, 잘못된 모델 ID.
- `POST /api/recommend`: 정상, 입력 누락, 예산 초과, 호환성 오류.
- `POST /api/images`: 정상 3개 이하, 중복 제거, 0건, 타임아웃, API 오류.
- 외부 API는 테스트에서 모킹. 실제 검색 키/호출 없이 CI 통과해야 함.

### E2E 테스트 (Playwright)
1. 홈페이지 → 모델 선택 → 환경·성향·예산 입력 → 결과 표시.
2. 부품 교체 → 총비용/중량 갱신.
3. 프리셋 저장 → 새로고침 → 복원.
4. 이미지 검색 결과 클릭 → 원본 페이지 링크 존재.
5. 검색 장애 → 기본 이미지와 오류 문구 표시, 추천 기능 유지.
6. 키보드만으로 주요 기능 실행.
7. `prefers-reduced-motion`에서 모션 최소화.

## 화면 검증
- 375px: 단일 열, 가로 스크롤 없음, 버튼 최소 44px.
- 768px: 카드/폼 정상 재배치.
- 1440px: 최대 너비와 그리드/여백 유지.
- 한국어 줄바꿈, KRW·g/kg 포맷 확인.
- 이미지 alt/출처/유사 이미지 안내 확인.
- 애니메이션 60fps 목표, 주요 모션 650ms 이내.

## 보안 테스트
- API 키 및 service role 키가 브라우저 소스/네트워크 응답에 없는지 확인.
- `javascript:`/`data:` 이미지 URL 차단.
- HTML 삽입 문자열이 텍스트로만 표시되는지 확인.
- 과도한 API 호출 시 제한 응답 확인.
- Supabase RLS 및 익명 쓰기 차단 확인.

## 배포 절차
1. GitHub에 소스 업로드(`.env.local` 제외).
2. Vercel에 저장소 연결.
3. Node.js 22 런타임 설정 및 `dist` 정적 출력 확인.
4. Vercel 환경변수에 OpenAI/Supabase/이미지 검색 키 입력.
5. Supabase 운영 DB에 마이그레이션 및 검증된 데이터 적용.
6. Preview 배포에서 모든 E2E 시나리오 확인.
7. Production 배포 후 `/api/models`, `/api/recommend`, `/api/images` 스모크 테스트.
